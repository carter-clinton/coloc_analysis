## qtl_coloc_snp_name_mismatch — Phase 2 coloc reports too_few_snps / n_snps_overlap=0 despite harmonized variants
- **Date:** 2026-04-20
- **Error patterns:** too_few_snps, Cannot extract SNP names from GWAS fit, n_snps_overlap=0, annotate_susie, no 'dimnames' attribute for array, variants_exceed_threshold, identity LD, fit.rds pip NULL, alpha colnames NULL
- **Root cause:** TWO compounding defects. (1) run_susie_rss.R called coloc:::annotate_susie with an unnamed identity LD matrix built via diag(nrow(subset)) when the LD reference was flagged variants_exceed_threshold (universal in T1 EUR). annotate_susie internally calls .susie_setld which indexes LD by credible-set names — this errored on unnamed LD and the surrounding tryCatch silently returned the un-annotated fit. 10 of 40 fits affected (only those with >=1 credible set). (2) run_qtl_coloc.R assumed GWAS and QTL share a variant naming convention (they don't — rsid vs chr_pos_ref_alt across builds) and that the LD .rds is a bare matrix (it's a list with {R, variants, use_identity, status}).
- **Fix:** (a) In run_susie_rss.R, attach snp_names as dimnames(R) before annotate_susie when R is unnamed. (b) In run_qtl_coloc.R, match via qtl_df$rsid (build-invariant) and handle LD .rds as list with R populated / use_identity / bare matrix. Regenerate the 10 affected Phase 1 fits via targeted `snakemake --cores N` on the specific .fit.rds targets.
- **Files changed:** src/legacy/region_analysis/scripts/run_susie_rss.R, src/snakemake/scripts/run_qtl_coloc.R

## ta_r3_w1_snp_id_overlap_zero — ta-r3 W1 PSD-regularized SuSiE-RSS fitter aborts with `Error: length(overlap) > 0 is not TRUE` for chr:pos sumstats
- **Date:** 2026-05-06
- **Error patterns:** length(overlap) > 0 is not TRUE, refit_sh2b3_psd_regularized.R:123, intersect rownames(R) sub$SNP_ID, chr:pos vs rsid, harmonized sumstats, SH2B3_12q24, hypertension stroke t2d, susie_rss, PSD-regularized fitter, variant-ID convention drift, ta-r3 W1, 12:111000057
- **Root cause:** Variant-ID convention drift between harmonized sumstats and per-region 1KG-EUR LD reference. The ta-r3 W1 fitter scaffolded in commit bccd0d6 (src/R/regularization/refit_sh2b3_psd_regularized.R) does a naive `intersect(rownames(R), sub$SNP_ID)` at line 122 with no chr:pos<->rsid bridge. asthma + bmi harmonized sumstats use rsid SNP_IDs (e.g. "rs7957299") and bypass the bug; hypertension + stroke + t2d harmonized sumstats use chr:pos (e.g. "12:111000057") and the LD-ref $variants$SNP_ID is 100% rsid (895/895 for SH2B3_12q24.rds), so intersect() returns 0 and stopifnot() at line 123 aborts. Same class as 2026-04-20 qtl_coloc_snp_name_mismatch entry; recurring because the prior fixes at commits 069b34f + 7d54183 were inline-only (run_qtl_coloc.R + run_susie_rss.R), not factored into a reusable utility.
- **Fix:** (a) Extract chr:pos<->rsid bridge as src/R/regularization/snp_id_bridge.R::bridge_snp_id_to_ld_ref(). Behavior contract: never regresses overlap; bridges ONLY when sumstats SNP_ID is chr:pos / NA / blank AND LD-ref has a clean rsid for the same (CHR, POS) tuple. Idempotent. (b) Wire bridge_snp_id_to_ld_ref() into refit_sh2b3_psd_regularized.R immediately upstream of the intersect() gate. No changes to regularization math, susieR call, or output schema. (c) Add tests/testthat-phase1/test_refit_sh2b3_psd_snp_id_bridge.R as failing-test-first regression covering all 5 EUR traits at SH2B3_12q24 (hypertension 0->589, stroke 0->622, t2d 0->863, asthma 700->701, bmi 170 unchanged). 4 atomic commits: 728d760 (test) + ad19818 (feat) + 12274a2 (docs+state+gitignore) + ce4e074 (drain confirmation). 12 LSF jobs redispatched (asthma+hypertension+stroke+t2d × 3 lambdas; bmi × 3 skipped — bridged re-fit binary-identical), all 12 drained ~5 min later, all 15 .fit.rds present at results/fine_mapping_psd_regularized/.
- **Files changed:** src/R/regularization/snp_id_bridge.R (NEW), src/R/regularization/refit_sh2b3_psd_regularized.R (MODIFIED), tests/testthat-phase1/test_refit_sh2b3_psd_snp_id_bridge.R (NEW), logs/sh2b3_psd_refit/sh2b3_psd_refit_dispatch.log (NEW; allowlisted), .planning/phases/ta-r3-audit-v2-driven-psd-and-r1-refire/ta-r3-W1-sh2b3-psd-regularized-refit-SUMMARY.md (NEW; bug-fix addendum), .gitignore (MODIFIED; logs/ -> logs/* + nested allowlist for sh2b3_psd_refit), .planning/STATE.md (stopped_at refresh)

## m3-gateb-nano-sample-axis-collapse — Gate B nano post_sample_qc returned N rows x 0 cols (sample axis collapsed; misread as empty-MT catastrophe)
- **Date:** 2026-06-03
- **Error patterns:** post_sample_qc, 118903 rows x 0 cols, empty-MT catastrophe signature, _assert_checkpoint_nonempty, sample axis collapsed, call_rate sample filter, sqc.call_rate >= 0.98, MIN_CALL_RATE_SAMPLE, nano interval chr22:16000000-18000000, Gate B nano, filter_cols dropped all samples, AoU ACAF FT no-call, scale-dependent QC metric, hl.sample_qc, returned empty MT
- **Root cause:** SCALE-DEPENDENT QC FILTER DEGENERATE ON A SMALL INTERVAL -> SAMPLE-AXIS COLLAPSE MISREAD AS EMPTY-MT CATASTROPHE. The unguarded call_rate sample filter (src/python/aou_ld_panel.py:1460-1461: `hl.sample_qc` then `filter_cols(sqc.call_rate >= 0.98)`) computes each sample's call_rate over the variant rows currently in the MT. At post_sample_qc the MT is interval-filtered to a 2 Mb nano window (~118,903 variants) and split-multi but NOT yet variant-QC'd (variant_qc is Phase 3, downstream of this checkpoint). AoU's ACAF callset sets FT-failed genotypes to no-call, so on a tiny pre-variant-QC window every sample's call_rate falls below 0.98 (live-confirmed mean=0.7942 max=0.8503) -> filter_cols drops ALL samples -> 118903 x 0. The het filter directly below was already guarded by stdev>0; the call_rate filter had no analogous nano-degeneracy guard (the asymmetry was the bug). _assert_checkpoint_nonempty then halted with a MISLEADING canned "empty-MT catastrophe (0x0)" message even though this was an N x 0 sample-axis collapse, not the m3-W1 0x0 finalize catastrophe. H1 (real genome-wide bug) REFUTED — scale-dependent, passes at whole-chr22/genome scale. H3 (aux-join regression) ELIMINATED — post_split retained all cols after ancestry filter + relatedness anti-join. LESSON: a cheap-tier (nano) FAIL on a scale-dependent metric (any QC metric computed over variants-in-window, e.g. sample call_rate) is NOT a faithful scale-model and is NOT a substrate-pivot trigger; threshold validation for such metrics belongs to the whole-chromosome+ tier (Gate C). The "cheap-tier FAIL -> pivot" rule has an unstated precondition: the cheap tier must be a faithful scale-model.
- **Fix:** Het-style degeneracy guard pattern. (1) New constant MIN_VARIANTS_FOR_SAMPLE_CALLRATE=500_000 (nano ~59.5K/Mb; whole-chr22 ~2.4M; never trips at whole-chromosome-or-larger, always trips at nano). (2) Guard the call_rate filter: when in-scope variant count < floor, SKIP the filter, log the call_rate distribution loudly, keep all samples, set sample_callrate_filtered=False — mirroring the het stdev>0 precedent. (3) Truthful provenance: constant into _collect_provenance.params; runtime outcome sample_callrate_filtered threaded into the post_sample_qc sidecar via a new _write_sidecar kwarg + added to _SIDECAR_COMPARE_EXCLUDE_FIELDS (avoids spurious resume invalidation since the outcome is a RESULT, not an INPUT). (4) Branch the _assert_checkpoint_nonempty message: rows>0/cols==0 => "sample axis collapsed during QC (NOT the 0x0 finalize bug)"; cols>0/rows==0 => variant-axis analogue; true 0x0 => existing finalize-catastrophe message preserved verbatim. (5) Faithful regression: --missingness knob on the synthetic fixture (default 0.0, backward-compatible) so call_rate<1.0 is achievable; pure-Python RED-first tests + 2 hail-gated integration tests (guard-skip-cols-retained / above-floor-filter-still-drops-bad-sample). LIVE-VERIFIED at Gate B nano re-fire #3 (HEAD 9f0c837): SKIP line printed exactly; sample axis survived end-to-end on all 3 cohorts (AFR 18648x74065, AFR-pca-selfid populated, EUR 10199x221572); _assert_checkpoint_nonempty silent.
- **Files changed:** src/python/aou_ld_panel.py (MODIFIED), tests/m3/fixtures/build_synthetic_mt.py (MODIFIED; --missingness knob), tests/m3/conftest.py (MODIFIED; synthetic_mt_path_missing fixture), tests/m3/test_aou_ld_panel_local.py (MODIFIED; 5 pure-Python RED-first + 2 hail-gated tests). Commits: e5bf0e7 (RED) + fad2847 (fix) + 9f0c837 (live-verified HEAD). Design: docs/superpowers/specs/2026-06-03-nano-sample-axis-callrate-guard-design.md. Confirming forensics: .planning/debug/m3-W2-gateB-nano-FAIL-diagnostics.md.

## m3-empty-mt-success-before-validate — Hail mt.checkpoint() writes a lying `_SUCCESS` over 0-byte contents (W1 catastrophe class; recurred as the W2 empty-final)
- **Date:** 2026-05-21 (W1) / 2026-06-10 (W2 final-merge recurrence, recovered 2026-06-11)
- **Error patterns:** _SUCCESS present but entries empty, 0x0 MT, 0-byte entries/rows/parts, count_cols=0 count_rows=0, schema-only MatrixTable, mt.checkpoint contract violation, finalize on empty, _assert_checkpoint_nonempty never ran, no traceback no 'wrote final' print, driver killed mid-finalize, lying success marker, empty final MT, mt_afr_qc.mt 0x0, mt_afr_pca_selfid_qc.mt empty, $2100 burn schema-only
- **Root cause:** Hail's `mt.checkpoint()` writes the `_SUCCESS` marker on **driver-side tasks-reported-complete accounting, NOT contents validation**. Two failure surfaces in this class: (W1, 2026-05-21) under the aggressive `spark.executor.cores=1/mem=5g` OOM-remediation profile + v8 partition explosion, executor tasks silently truncated after writing Parquet footers → `_SUCCESS` over footer-only `entries/rows/parts/` (true 0x0). (W2, 2026-06-10) the genome traversal + 22 per-chrom intermediates were all populated and correct, but the driver was **killed in the `aou_ld_panel.py:1973→1974` window** — between the `_SUCCESS`-writing `mt.checkpoint()` and the `_assert_checkpoint_nonempty` validation — by an external kill (a stray browser navigation away from the JupyterLab tab during the finalize flush), NOT a config/OOM bug (the LARGER AFR-primary + EUR finalized fine under identical config, and `_SUCCESS` was written so finalize ran through the het aggregate). Verification methodology that MISSED it: gsutil `_SUCCESS` glance + Spark-UI cascade-signature inference, neither of which traverses `entries/rows/parts/` for actual byte payload.
- **Fix:** (defensive, landed) `_validate_checkpoint_populated(uri)` — contents-validating resume-gate (`_SUCCESS` + `entries/rows/parts/` with ≥1 part > 1 KB), replacing bare `_has_checkpoint` in the auto-resume state machine (load_qc_cohort lines ~1631/1649/1659/1675, with an explicit empty-MT-pattern fall-through to auto_fresh); `_assert_checkpoint_nonempty` post-write count assertion. (recovery, W2) intermediates were intact → **finalize-only re-drive** from the 22 `…post_variant_qc_chrN`, proven in a read-only `_scratch` dry-run (du + count_cols/count_rows + .describe), promoted via `gsutil -m rsync -r -d` scratch→live, re-verified at the data layer. NOT force_fresh=True. (durable, DESIGNED-NOT-APPLIED) atomic-final-write contract so a canonical `_SUCCESS` always implies validated contents — a `_VALIDATED` sentinel written only after the non-empty assertion + a `_final_is_trustworthy` consumer gate (AOU-2/AOU-4 currently read the final with NO contents gate); see DURABLE-FIX-DESIGN-atomic-final-write.md, route via /gsd-plan-phase --gaps before GATE 3. LESSON: `_SUCCESS` is never evidence of data — verify du-floor + counts; and the finalize window is fragile to external kill (keep the tab foregrounded; the durable fix closes it).

## m3-afr-sensitivity-selfid-noop — sensitivity=True cohort came out byte-identical to the primary (silent no-op; self-report filter never applied)
- **Date:** 2026-06-08 (fixed) / 2026-06-11 (clean cohort banked)
- **Error patterns:** sensitivity == primary, byte-identical cohort, membership-identical 73122, self_report never sourced, silent no-op, skip-guard masks not fixes, `if sensitivity and "self_report" in mt.col`, SENS_FILTER_VERSION, WhatRaceEthnicity_Black, race_source_value, R9 concept_name drift "What Race Ethnicity: Black", self_report_table_path missing, mt_afr_pca_selfid_qc contamination, passes count sanity check undetected
- **Root cause:** TWO compounding defects. (1) A silent-skip guard `if sensitivity and "self_report" in mt.col:` made `sensitivity=True` behave exactly like `sensitivity=False` whenever the `self_report` column was absent — and it is ALWAYS absent on the raw WGS MT (self_report lives in the CDR person table, BigQuery-only; it must be SOURCED via import_table + annotate_cols). So the sens cohort silently became a byte-identical copy of the primary (73,122 samples) and PASSED the count sanity check undetected — the contamination tell (byte-identical to primary) was the only signal, NOT a count anomaly. (2) the survey-answer match was on a DISPLAY string that drifted across CDR revisions (R9 concept_name became "What Race Ethnicity: Black"), zero-matching the old literal. Same skip-guard-masks class as the nano sample-axis collapse — a guard that SKIPS work below a condition hides the bug unless the skipped path is shown valid.
- **Fix:** (a) source self_report explicitly: thread `self_report_table_path` (CANONICAL `gs://rw-migration-aou-rw-476cdac2/ld/aux/self_report/self_report.tsv`, regenerated in-perimeter against the v8 CDR — see [[reference_aou_rw2_mirror_vpcsc]]) into load_qc_cohort; the extractor (`extract_aou_self_report.py`) emits the STABLE `race_source_value` code, and the filter matches on `WhatRaceEthnicity_Black` (SENS_FILTER_VERSION=2), not the drifting display string. (b) assert the result is a STRICT non-empty subset + path-isolated checkpoint (`_pca_selfid` token in `_intermediate_checkpoint_uri`) — verify the path-builder, not just the count. Live-confirmed in-run: `74,576 → 63,312` self-report subset; final banked cohort 62,557 × 20,817,925 (strict subset, contamination tell absent, .describe shows self_report). NOTE: this is also why the AFR-sens Cell 4 edits (self_report_table_path + force_fresh) are MANUAL and NOT in the committed notebook template — see the aou-ld-pipeline skill's baked-vs-manual table.
- **Files changed:** src/python/aou_ld_panel.py (MODIFIED; SENS_FILTER_VERSION=2, self_report sourcing), src/python/extract_aou_self_report.py (race_source_value). Commits: 06b8a97 + the 005d651→9b86b99→8609170→0fc3109 TDD chain. Session: .planning/debug/m3-W2-afr-sensitivity-selfid-noop.md. Memory: [[feedback_skip_guard_masks_not_fixes]].
