# Phase quick-260629-402 Plan 01: Bound the 2nd npz-convert OOM head in content_verify_npz Summary

Closed the SECOND, still-unbounded full-matrix OOM head on the native-plink square LD path by
routing `content_verify_npz`'s square branch through the proven `pln._is_symmetric_blocked` and
adding a co-located, memory-bounded `pln._strict_upper_is_zero_blocked` for the banded branch —
reason strings byte-identical, diagonal/flag checks untouched.

## Blast-radius finding

The prior fix (3eac803) bounded only `read_square_bin`'s symmetry check. But the in-process
per-region D-M3-10 gate `content_verify_npz` (`src/python/run_native_ld_panel.py`, call site
~line 475) **RELOADS the full `.npz`** (~39 GiB at `n_var=102,421`) and then ran the IDENTICAL
unbounded checks one function later:

- **Square branch (~line 228):** `np.allclose(ld, ld.T, atol=1e-4)` materializes several full
  `n_var**2` float32 temporaries on top of the matrix — measured **~156 GiB (~4x matrix peak)**
  at `n_var=102,421`, which **OOM-kills the 128 GB re-fire VM** → 0/276 AGAIN (same failure class
  as region 1 in m3-02e-T4).
- **Banded branch (~line 234):** `np.allclose(np.triu(ld, k=1), 0.0)` builds a full `n_var**2`
  `np.triu` copy — the SAME OOM class. Off the square re-fire path, but in the same shared gate,
  so it would have re-introduced the head as soon as a banded run used the gate.

So `content_verify_npz` was the second OOM head: the gate that proves "markers are NOT evidence"
was itself the thing that crashed the VM right after `read_square_bin` had been made safe.

## The fix

- **Square branch:** `np.allclose(ld, ld.T, atol=1e-4)` → `pln._is_symmetric_blocked(ld, atol=1e-4)`
  (the proven bounded helper, reused — no duplication; `pln` alias already imported at line 97).
- **Banded branch:** `np.allclose(np.triu(ld, k=1), 0.0)` → `pln._strict_upper_is_zero_blocked(ld)`,
  a NEW helper co-located directly after `_is_symmetric_blocked` in `plink_ld_to_npz.py`. It does
  `np.triu` on each row BLOCK with offset `k=i+1` (global column > global row), bounding the
  transient to ~`block * n_var` entries (~420 MB at block=1024, n_var≈1e5) and matching
  `np.allclose(np.triu(m, k=1), 0.0)` default-atol semantics exactly.
- **Both reject reason strings are BYTE-IDENTICAL** (`"not symmetric (atol 1e-4)"` /
  `"banded npz has non-zero strict upper triangle"`). The diagonal checks (`np.diag` O(n) copy)
  and the `lower_triangular` flag check are UNCHANGED.

Follows [[feedback_extract_reusable_utilities]] (reusable utility + failing-first regression for a
recurrent bug class).
