<objective>
Close the READ-SIDE hole of the durable atomic-final-write contract (Phase 2,
item 1). Phase 1 (commit f931446) landed the producer-side `_VALIDATED` stamp and
the contents-only `_final_is_trustworthy(uri)` gate — but NO consumer calls it, so
the AOU-2 notebook still reads the final MT blind (`hl.read_matrix_table` with no
gate). A bad final (the 2026-06-10 empty-`_SUCCESS`-over-0-byte catastrophe class)
would propagate silently into LD compute.

This plan adds a single source-level reader `read_final_cohort_mt(uri)` that calls
the gate and RAISES a loud, actionable RuntimeError on failure BEFORE reading, then
wires AOU-2 cell 4 to it for both `mt_afr_qc.mt` and `mt_eur_qc.mt`.

Purpose: the protective value of the Phase-1 gate is unrealized until a consumer
actually calls it. AOU-2 cell 4 is the ONLY direct final-MT reader (AOU-4 reads
only AOU-2 `.rds` products), so wiring it here closes the hole.

Output: `read_final_cohort_mt` helper + RED→GREEN tests + AOU-2 cell-4 wiring +
design-doc status update. Code-only — chr22 smoke and the live fire stay deferred
behind GATE 1 (Carter holds the cost trigger).

EXPLICIT NON-GOALS (do NOT do): chr22 smoke (needs the live cluster);
the `_qc_checkpoint_uri` `file://` footgun (item 3, latent, inert in production);
any cluster / gsutil / notebook-execution action.
