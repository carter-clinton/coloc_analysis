# Quick 260628-244 — Fix chr-prefix mismatch in native-plink LD loop verify

**Created:** 2026-06-28
**Branch:** m3-W2-aou-deltas

## Problem

The 276-region AFR native-plink LD loop (m3-02e-T4) ran ~17 h on the AoU 1TB VM and
banked **0 of 276** `.npz`. Region 1 failed verify with
`n_var mismatch: .ld.bin implies 102421 but the window .bim has 0 rows`. Bank is
gated on verify success, so no `.npz` was written/uploaded and the raw `.ld.bin` was
never reclaimed → scratch climbed to 82% (kill was 174 GiB from full).

**Root cause (confirmed on real AoU data):** the AoU GRCh38 cohort `.bim` uses
`chr`-prefixed contigs (`chr1`; real-data check: region-1 chr1 window = 102,421 vars,
col0 literally `chr1`), while `config/ld_regions.tsv` `chr` is bare numeric (`1`).
plink1.9 normalizes the prefix so `--chr 1` correctly produced the `.ld.bin`, but
`_window_bim_n_var` did a literal `str(parts[0]) == chrom` compare that never strips
`chr` → 0 rows kept → mismatch. The existing fake-plink test stub `_n_var_in_window`
used the *same* literal compare and a bare `.bim`, so CI was blind to it.

## Tasks

1. **Fix** `src/python/run_native_ld_panel.py`: add `_chrom_match_key()` (strip a
   leading `chr`/`CHR`, mirroring plink1.9); compare normalized keys on both sides in
   `_window_bim_n_var`; keep kept-line content verbatim (downstream `ld_npz_to_rds.R`
   strips the prefix before the GWAS join). Normalize the temp window-`.bim` filename
   to the bare key too.
2. **Regression** `tests/m3/test_run_native_ld_panel.py`: failing-first parametrized
   unit test of `_window_bim_n_var` across all four prefix combinations
   (`chr12`/`12`, `12`/`chr12`, both-prefixed, both-bare) asserting the true in-window
   count and verbatim kept contig.

## Verify

- `pytest tests/m3/test_run_native_ld_panel.py` green (new mismatched-prefix cases
  fail pre-fix, pass post-fix); `tests/m3/test_plink_ld_to_npz.py` unaffected.
- Real-data pre-flight on the VM before re-fire: fixed `_window_bim_n_var` over the
  cohort `.bim` for region 1 returns ~102,421.
- Push to origin `m3-W2-aou-deltas`; AoU agent re-pulls + re-fires from region 1.
