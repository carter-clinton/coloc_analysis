## The remedy chosen for H, and why — resolve orientation, do not merely exclude

The brief offered two shapes. **Neither alone is sufficient; the plan takes (b), implemented
using (a)'s key as its matching mechanism.**

**Why not (a) alone** — "make the sumstats side carry `chr:pos:ref:alt` so the existing
SNP_ID branch starts matching". It disambiguates multiallelics, and that is real. But it
**answers the wrong question about sign**: a swapped-orientation row simply fails to match
and is silently dropped, so (a) converts an invisible sign error into an invisible overlap
loss. On a panel whose entire purpose is to *raise* AFR overlap over the n=661 1kG reference,
discarding every legitimately-swapped variant is an unforced scientific cost. Worse, (a)
never asks the orientation question at all, so any variant that reaches the fit by some other
route still carries a wrong-signed z.

**The remedy — (b), allele-aware with orientation resolution:**

| Case | Disposition | Counter |
|---|---|---|
| `chr:pos` matches AND (REF,ALT) matches exactly | KEEP, `orient = +1` | `ld_allele_exact` |
| `chr:pos` matches AND (REF,ALT) is transposed | KEEP, **`orient = -1` → z NEGATED** | `ld_allele_flipped` |
| alleles are palindromic (A/T, T/A, C/G, G/C) | **DROP** | `ld_allele_dropped_palindromic` |
| `chr:pos` present in panel, no compatible allele pair | **DROP** | `ld_allele_dropped_mismatch` |
| >1 panel row is compatible at that `chr:pos` | **DROP** | `ld_allele_dropped_ambiguous` |
| REF or ALT missing / empty / `"N"` / NA on either side | **DROP** | `ld_allele_dropped_unusable` |
| `chr:pos` absent from the panel entirely | not matched (ordinary non-overlap) | — not a defect, not counted |

Implemented as **two `match()` calls on 4-keys** — `chr:pos:REF:ALT` and the same key with
REF/ALT transposed — so it is O(n log n), loop-free, and multiallelics are disambiguated **by
construction** rather than by a tie-break someone has to trust.

### Scientific consequences, stated plainly

1. **Flipping is not excluding, and the difference is material.** Because ALT is the coding
   allele on BOTH sides, a transposed row is *legitimate data* whose only defect is
   bookkeeping. Negating z restores it at zero cost. SuSiE's PIP is invariant to the coding
   of any single variant; only the internal z sign changes.
2. **Reported `BETA`/`SE` are NOT flipped.** They stay in **sumstats effect-allele
   orientation** in `credible_sets` and every downstream table. The flip is strictly an
   internal alignment of z to the panel's coding allele. The manuscript's reported direction
   of effect does not move. (Flipping BETA in the output would silently change a published
   effect direction — refused.)
3. **Palindromic rows are DROPPED, not kept.** This is the deliberate rigor-over-yield call,
   and its justification is specific to this panel, not boilerplate: because
   `ld_npz_to_rds.R`'s liftover does not complement alleles, palindromes are the **only**
   class in which a strand-inverted chain block produces an *exact match that is silently
   sign-wrong*. Every other class self-reports. Dropping them removes the sole invisible
   failure mode. Expected cost is roughly the palindromic fraction of overlap (single-digit
   percent), which is affordable against `min_ld_coverage = 0.5` at realized AFR overlap ~10³
   (`m3-04c-BLAST-RADIUS.md:105-107`). **Not configurable** — a knob here is another silent
   lever.
4. **No new fatal threshold is invented.** Drops reduce realized overlap; the EXISTING
   production gate (`min_ld_overlap=50`, `min_ld_coverage=0.5`, `min_ld_min_use=10`) and the
   `260805-23d` authoritative mandate decide fatality, unchanged.
