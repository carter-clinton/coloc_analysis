The cairo PNG output is fully deterministic when rendering identical ggplot content: same data → same PNG bytes. Since the disk-derivation pathway produces the same per-trait CS counts as the prior literal-list values (which was the explicit T1 design intent — "self-correction-discipline alignment, NOT a numeric correction"), the PNG rendered with byte-identical output. Git correctly excluded the unchanged PNG from the commit because there was no content to stage.

**The PDF, by contrast, did change** (HEAD blob `3cc91162` → new blob `ae8a6008`) because cairo PDF output embeds wall-clock timestamps in the PDF metadata stream, which differ between renders. This means the PDF re-render did get committed, satisfying the "fig3 re-rendered" intent of the plan.
