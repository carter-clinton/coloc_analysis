### Gate order and placement (both inside the `mode == "square"` path)
- The window `.bim` read / `pre_window_n_var` computation happens first (cheap,
  existing code). Then, in order:
  1. **Feasibility ceiling FIRST** (needs only the count): if
     `pre_window_n_var > max_n_var` → `result["status"] =
     f"deferred_infeasible_square: n_var={pre_window_n_var} > ceiling={max_n_var}"`,
     no occlusion detect, no excludelist, no plink, no uploads; panel row
     appended; `return result` (the loop continues; artifacts: NONE).
  2. **Anomaly gate SECOND** (after `detect_occluded_variants`, BEFORE any
     excludelist write / plink): if
     `len(occluded_ids) > _OCCLUSION_ANOMALY_FRACTION * pre_window_n_var` →
     `result["status"] = f"deferred_occlusion_anomaly: {len(occluded_ids)}"
     f" occluded of {pre_window_n_var} (ceiling {int(...)})"` — NOTHING is
     excluded (clause (d): "NOT auto-excluded"), no manifest, no excludelist,
     no plink, no uploads; panel row appended; return; loop continues.
- `n_dropped_occluded` stays `None` on both deferral paths (nothing dropped —
  the observed count lives in the status string, following the existing
  `"error: …"` detail-in-status pattern).
- Existing status vocabulary precedent: `ok` / `verify_failed` / `error: …` /
  `skipped_idempotent`. The two new statuses follow it.

### Constants and CLI
- `_OCCLUSION_ANOMALY_FRACTION = 0.0005` — a module-level named constant with a
  comment citing trsx5 clause (d). **NOT CLI-tunable** (it is pre-registered;
  a knob would invite silent deviation).
- `--max-n-var` CLI flag, **default 120000**, threaded through
  `run_native_ld_panel()` → `process_region()`. The default MUST equal the
  consumer ceiling `m3_convert_max_n_var` in `config/pipeline.yaml:393` — and a
  test must PIN that equality by reading the YAML (the debug file's thesis:
  "nobody carried the number back to the producer"; the pin prevents the two
  numbers drifting apart again).
- `--fail-fast` semantics UNCHANGED: it halts on the first `status != "ok"`,
  which now includes deferrals. Correct and deliberate: Stages A/B (fail-fast)
  contain only feasible, far-below-ceiling regions; Stage C runs without
  fail-fast so deferrals continue the loop. Document this in the flag's help or
  a comment; do not special-case deferrals.
