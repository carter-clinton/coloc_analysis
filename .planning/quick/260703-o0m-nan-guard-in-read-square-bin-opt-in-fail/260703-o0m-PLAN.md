## Task 1 — Defect 3: NaN-specific error in `read_square_bin` (TDD)

**Why:** at 2d23d67 `read_square_bin` does reshape → diagonal → `_is_symmetric_blocked`
with no NaN check, so a plink `0/0 -> NaN` entry raises the MISLEADING "square LD
is not symmetric" (`NaN != NaN` breaks the equality). The check correctly *rejects*
the matrix but *misnames* the cause. Fix = detect NaN FIRST and raise a
NaN-specific error naming the likely source variant rows; keep the diagonal +
symmetry checks intact AFTER it.

**do_not exception:** `HANDOFF.json`/`STATE.md` say keep `read_square_bin` frozen.
This add is a *diagnostic strengthening* (raises earlier + clearer, never loosens
the diagonal/symmetry/OOM checks — a NaN still raises). Approved by Carter
(AskUserQuestion 2026-07-03). The do_not note is amended in the docs commit.

- **RED** — `tests/m3/test_plink_ld_to_npz.py` +`tests/m3/test_nan_guard.py`:
  - Update `test_read_square_bin_raises_on_monomorphic_nan`: KEEP the realistic
    fingerprint (row/col k = NaN, `np.fill_diagonal(m,1.0)` so diagonal stays 1.0),
    assert `ValueError` with `"NaN" in msg`, `"not symmetric" not in msg`,
    `str(k) in msg`.
  - New `test_nan_guard.py`: (a) clean symmetric matrix → `read_square_bin` returns m,
    `_has_any_nan_blocked` False; (b) whole-row NaN + diagonal 1.0 → `nan_variant_indices`
    lists k first, `read_square_bin` raises NaN error naming k; (c) sparse 2-cell NaN
    (m[a,b]=m[b,a]=NaN) → `_has_any_nan_blocked` True, indices include a and b;
    (d) NaN-free ASYMMETRIC matrix → still raises `"not symmetric"`.
  - Run: expect FAIL (attrs `_has_any_nan_blocked`/`nan_variant_indices` absent;
    old code raises "not symmetric"). Commit RED.
- **GREEN** — `src/python/plink_ld_to_npz.py`:
  - Add `_has_any_nan_blocked(m, block=1024)` and `nan_variant_indices(m, block=1024,
    max_report=32)` (ranked-by-NaN-count worst-first, capped — NOT `.all(axis=1)`,
    which returns [] on the real diagonal-1.0/sparse fingerprint) immediately before
    `_strict_upper_is_zero_blocked`. Both block-wise (module-level `np`, no full
    n_var**2 temporary).
  - In `read_square_bin`, after `m = arr.reshape(...)` and BEFORE the diagonal check,
    insert the NaN block raising the NaN-specific `ValueError`.
  - Run `pytest tests/m3/test_plink_ld_to_npz.py tests/m3/test_nan_guard.py` → GREEN. Commit.
- **verify:** the two files pass; the pre-existing symmetric/diagonal/OOM tests still pass.
- **done:** NaN → NaN-specific error naming culprits; asymmetric-no-NaN → "not symmetric".

## Task 2 — Defect 4: opt-in `fail_fast` region gate (TDD)

**Why:** `process_region` swallows every error into `status='error: ...'` and the
loop continues, so a broken region 1 cannot halt a ~276-region / multi-day fire.
Add an OPT-IN gate (default off preserves the resume-safe continue).

- **RED** — new `tests/m3/test_gate.py` (monkeypatch `run_native_ld_panel.process_region`,
  `.alp._read_manifest`, `._filter_ancestry`, `._shard_rows` to feed controlled rows):
  - `fail_fast=True` + a middle region status `error:...` → raises `RegionGateError`,
    `.region_id`/`.status` correct, later region NOT processed.
  - default (`fail_fast` omitted) → continues, returns all statuses incl. the error.
  - Run: expect FAIL (`RegionGateError`/`fail_fast` absent). Commit RED.
- **GREEN** — `src/python/run_native_ld_panel.py`:
  - Add `class RegionGateError(RuntimeError)` (carries `region_id`, `status`) just
    above `run_native_ld_panel`.
  - Add keyword-only `fail_fast: bool = False`; after `results.append(res)` raise
    `RegionGateError(...)` when `fail_fast and str(res.get("status")) != "ok"`.
  - Add `--fail-fast` (`action="store_true"`) in `main()`; thread `fail_fast=args.fail_fast`.
  - Run `pytest tests/m3/test_gate.py` → GREEN. Commit.
- **verify:** gate halts on non-ok under fail_fast; default continues.
- **done:** region-1 gate can actually halt a fire; default behaviour unchanged.
