## The failure semantics chosen for T-A, and why

**A HARD `stop()`.** Not a status field, not a machine-detectable JSON key.

The alternative requires the JSON to be written and the process to exit 0, so Snakemake marks the job DONE and `snakemake all` completes green. The gate then becomes a post-hoc scan someone must remember to run — **which is the exact failure class this whole sweep is about.** The `resolved == opened` receipt ALREADY EXISTED in every region's JSON and `estimate_s` log, and nobody read it. Write-only observability is not observability.

A `stop()` makes the DAG itself the gate: the region's job FAILS, `snakemake all` cannot complete, and with `--keep-going` the blast radius is one region rather than the fire.

The message is one line, with a stable greppable prefix and every number an operator needs:

```
LD_DECLARED_REJECTED: reason=<code> declared=<path> region=<id> ancestry=<anc>
overlap=<n> coverage=<f> min_ld_overlap=50 min_ld_coverage=0.5 min_ld_min_use=10 remedy=...
```

Reason codes: `unreadable` · `no_matrix` · `use_identity` · `overlap_below_min_use`.

**There is deliberately NO per-run override flag** — adding one re-creates the silent path. The kill switch is the allow-list itself: `ld_read_path.ancestries: []` or `ld_read_path.enabled: false` restores today's behaviour for every ancestry in one config line.

**False-tripping was treated as the larger risk here** (cf. the P3 `gsutil` precedent): both guards fail OPEN, and the not-firing cases are tested explicitly at function level and end-to-end — `authoritative=FALSE` for every reason code, an accepted gate pass, a `partial_overlap`, the legacy `ld_dir_missing` / `ld_missing` / `ld_overlap_insufficient` guards, a bare 3-field legacy result, no `--ld-file` at all, and **a declared panel that does not exist yet** (the AoU `.rds` arrive over weeks; a gate that could not tell "not built" from "built and rejected" would abort every AFR region before the fire ran).

## ⚠️ BEHAVIOUR CHANGE — named plainly

**For allow-listed ancestries (AFR only, today), a region whose declared panel yields overlap below `min_ld_min_use` (10) now ABORTS the region.** Previously it fell through to an identity fit and was reported as `status="success"` with `ld_matrix="identity"`.

This is the intended tightening — an identity fine-map is precisely the outcome the 11-day fire exists to eliminate — **but it IS a behaviour change and it must be seen as one.** Sub-threshold but ≥ 10 still returns the DECLARED panel under `partial_overlap`, unchanged.

For **EUR and TRANS this guard can never fire**: `assert_declared_ld_authoritative()` returns `invisible(TRUE)` immediately when `authoritative` is not TRUE, and off the allow-list `--ld-authoritative` renders `false`.

## 🔴 DISCLOSED RESIDUALS — every one unhedged

### 1. BLOCKER-D is PARTIAL. Do NOT read it as closed for the large regions.

The `.npz`'s own `ld` key is a **dense `float32`** written by the **FROZEN** producer (`src/python/plink_ld_to_npz.py:253`). A perfectly bounded reader must therefore still hold **one dense copy on read**:

| Target | n_var | dense float32 on read |
|---|---|---|
| SH2B3 `m2_region_00040__sub14` (the Track A anchor's panel) | 75,497 | **22.8 GB** |
| MC4R class | — | **67.3 GB** |
| FTO / HLA class | ~372,000 | **~553 GB** |

This makes SH2B3's subregion **feasible on a big-memory node** and makes the large targets **fail fast at the `m3_convert_max_n_var` ceiling (in seconds, naming region / n_var / implied dense bytes) instead of OOM-killing after hours.** It does **NOT** make them convertible. A genuinely sparse `.npz` is a PRODUCER-side change on a frozen contract and is out of scope.

### 2. `snakemake all` is still NOT self-sufficient.

`resolve_ld_path` returns the first **EXISTING** path (`ld_panel.py:87`), so a not-yet-built chain head is SKIPPED rather than pulled in as a to-be-built input. `rule m3_convert_aou_afr_rds_all` makes the conversion invocable as **one operator command** — it does not make the DAG pull an unbuilt AoU panel in. `run_finemap` deliberately does NOT depend on the sentinel (that would force the AoU fire for every ancestry). The operator sequence is: arrival flags → `snakemake m3_convert_aou_afr_rds_all` → `snakemake all`. Same shape as the ingest side. Changing `resolve_ld_path`'s first-EXISTING semantics is out of scope here.

### 3. The defect-2 fix is applied UNCONDITIONALLY and therefore also touches the EUR/TRANS fallback loop.

`best_partial` now keeps the **BEST** overlap rather than the last one seen. That change is inside `load_ld_matrix` and is **not** gated by `authoritative`, so it is live on the EUR/TRANS path too. **A manuscript is in submission, so this is stated explicitly rather than left implied.**

It is **INERT for EUR/TRANS today — verified empirically in Task 2, not argued.** `dir_candidates` lists two path strings per region (raw id and safe slug), but every LD-panel producer in this repo names its output via the **safe slug only** (`build_ld_rds_1kg_eur`, `ld_reference.smk:274-289`, output `{ancestry}/{region}.rds` with `{region}` = the safe wildcard). `BMI_5q13.3` is the only curated region whose id differs from its safe slug, and `ld_reference/{EUR,AFR}/BMI_5q13.3.rds` has **no producer** (`build_ld_rds` `KeyError`s — `REGION_METADATA` is keyed by the safe slug), while `TRANS/` has no rule at all. The candidate list therefore collapses to at most one real file and the selection rule cannot change which one is chosen.

### 4. New AFR abort behaviour (restated as a residual).

A declared AFR panel below `min_ld_min_use` now aborts the region where it previously identity-fitted and reported success. Intended tightening; still a behaviour change. See the section above.

### 5. Blast-radius findings E, H, I, J, K, L, M are UNTOUCHED.

In particular:

- **E** — `qtl_coloc.smk` reads the legacy 1kG panel while the GWAS fit it colocalizes used AoU. Mixed LD inside one `coloc.susie`. **This still blocks any GWAS×QTL colocalization.**
- **H** — the sumstats↔panel join is **allele-blind** (panel `SNP_ID` is GRCh37 `chr:pos:ref:alt`, harmonized AFR sumstats carry `chr:pos`, so everything degrades to the CHR/POS `match()` with REF/ALT ignored). **This still blocks trusting any AFR fine-map result.**

**Closing A/B/C/D unblocks the FIRE. It does NOT discharge the "trusting any AFR fine-map result" row of the gate table.** Say it plainly: a green fire produces panels that are correctly built, correctly declared and correctly opened — and whose variant-level orientation against the sumstats is still unverified.

Also untouched: **G** (orphaned TRANS chain head, `strict_aou_only` blind to it), **I/J/K** (panel-blind summary, false-alarming receipt, mutated `variant_catalog_fallback`), **L/M** (crosswalk drift detection, `status=partial` promotion).
