<failure_semantics_decision>
T-A asked for an explicit choice. THE CHOICE IS A HARD stop().

WHY. The alternative -- "a loud, machine-detectable status the DAG can gate on" --
requires the JSON to be written and the process to exit 0, so Snakemake marks the
job DONE and `snakemake all` completes green. The gate then becomes a post-hoc scan
someone must remember to run. That is the exact failure class this whole sweep is
about: the `resolved == opened` receipt ALREADY EXISTS in every region's JSON and
estimate_s log, and nobody read it. Write-only observability is not observability.

A stop() makes the DAG itself the gate: the region's job FAILS, `snakemake all`
cannot complete, and with --keep-going the blast radius is one region rather than
the fire.

SHAPE. The loud decision is NOT buried in load_ld_matrix. The loader stays a pure
function returning a structured rejection; a separate small function
assert_declared_ld_authoritative() -- defined in the FUNCTION PREFIX above
`option_list <-`, so _loader_functions_only() picks it up and tests can call it
directly -- is what stop()s. That keeps the whole thing behaviourally testable with
the existing harness instead of source-grep-only.

MESSAGE. One line, stable machine-greppable prefix, every number an operator needs:
  LD_DECLARED_REJECTED: reason=<code> declared=<path> region=<id> ancestry=<anc>
  overlap=<n> coverage=<f> min_ld_overlap=<n> min_ld_coverage=<f> min_ld_min_use=<n>
  remedy=<one clause>
reason codes: unreadable | no_matrix | use_identity | overlap_below_min_use

KILL SWITCH. There is deliberately NO per-run override flag: adding one re-creates
the silent path. The switch is the allow-list itself -- ld_read_path.ancestries: []
or ld_read_path.enabled: false restores today's behaviour for every ancestry in one
config line.

SCOPE OF THE BEHAVIOUR CHANGE -- NAME IT PLAINLY IN THE SUMMARY: for allow-listed
ancestries (AFR only), a region whose declared panel yields overlap <
min_ld_min_use (10) now ABORTS where it previously fell to an identity fit reported
as status="success" with ld_matrix="identity". That is the intended tightening --
an identity fine-map is the outcome the 11-day fire exists to eliminate -- but it IS
a change and Carter must see it named. Sub-threshold but >= 10 still returns the
DECLARED panel under partial_overlap, unchanged.
</failure_semantics_decision>
