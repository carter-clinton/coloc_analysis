## Scope

Audit the m3-W1 AOU-1 cohort-definition pipeline for producer/consumer drift bugs of the same class as the 260512-jd9 finding (URI/path/key construction that ignores a parameter that downstream consumers branch on; silent-overwrite class).

Bounded to these files:

- `.planning/notebooks/AOU-1_template.ipynb` — Cells 1-9 (post the 260512-ldj Cell 1 split into 1a + 1b)
- `src/python/aou_ld_panel.py` — ~520 lines, the module called by AOU-1 cells
- `.planning/notebooks/AOU-2_per_region_ld.ipynb` — downstream consumer of W1 checkpoints
- `.planning/notebooks/AOU-4_validation.ipynb` — downstream consumer of W1 cohorts + W2 outputs
- `.planning/phases/m3-aou-afr-ld-panel-build/m3-region-class-projection.tsv` — region-class metadata producer/consumer interface

Drift-class signatures audited:

1. URI/path construction that takes a subset of (ancestry, sensitivity, cohort, ancestry_method, qc_level, region_class, span_mb, version) where the consumer branches on a parameter the producer omits.
2. Cohort identifier columns (cohort_id / sample_id / subject_id / person_id) written without a discriminator the consumer expects.
3. Checkpoint mtime / freshness reads without verification against the run-version that produced the artifact.
4. Hardcoded ancestry string literals (`"afr"` / `"eur"`) where a parameterized path or dict key should be used.
5. Sensitivity branching at the consumer side but not the producer side — the 260512-jd9 mirror.
6. Region-class branching at the producer side but not exhausted at the consumer side.

## Why this audit

Rigor-defensible follow-on to 260512-jd9 ([[feedback_rigor_over_speed]]). The 260512-jd9 finding rules out one silent-overwrite path (primary vs sensitivity AFR cohorts), but the audit class is general — Cells 4-8 of AOU-1 will fire after Cell 3 closes (~45-90 min envelope from 2026-05-12T17:21:28Z), and any analogous drift at a per-region writer, EUR parity branch, or cohort_summary aggregator could silently corrupt downstream Wave 2 / Wave 3 / Wave 4 artifacts. A documented audit verdict (whether drifts found or no-drifts-found) is the reproducibility / reviewer audit trail.

This task does not pre-emptively edit source code. Source changes only land if a drift is empirically found; then under TDD per [[feedback_extract_reusable_utilities]] — failing-regression-first, then helper extraction, then green re-run. If no drifts are found, the audit verdict is itself the deliverable.
