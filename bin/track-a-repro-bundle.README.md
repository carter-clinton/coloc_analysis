# Track A Author-Reproducibility Bundle

Companion docs for [`bin/track-a-repro-bundle.sh`](track-a-repro-bundle.sh).

## 1. Purpose

Closes **Eval 4B** (*bidirectional provenance at file boundary*) of the
27-item Track A audit closure tracker
[`.planning/amendments/TRACK-A-AUDIT-RESPONSE-2026-04-26.md`](../.planning/amendments/TRACK-A-AUDIT-RESPONSE-2026-04-26.md).

Eval 4A (locked-scalar self-correction) closed in quick task `260426-04b`.
Eval 4B is the remaining half: Fig 3
([`src/R/figures/fig3_sh2b3_eur_collapse_forest.R`](../src/R/figures/fig3_sh2b3_eur_collapse_forest.R))
must be regeneratable in either direction:

1. **Forward (re-fire):** sumstats → identity-LD SuSiE re-fit
   (`scripts/fire_identity_ld_rerun.sh`, ~1 h LSF) → Fig 3.
2. **Backward (extract):** bundle tarball → cached identity-LD JSON tree → Fig 3.

This script builds the bundle that powers direction (2).

## 2. Policy reference

**DEC-2026-04-25-01** ([`.planning/DECISIONS.md:663-677`](../.planning/DECISIONS.md))
keeps the ~160 MB `results_identity_ld/` tree out of git.

The bundle output also lives outside git:
[`results/track-a-bundles/`](../results/track-a-bundles/) is covered by

bundle is intended for **manual** OSF deposit at the amendment record
[`osf.io/az52u`](https://osf.io/az52u).

## 3. What's in a bundle

Default contents (JSON-only; ~90 MB compressed):

| Path inside tarball | What |
|---|---|
| `BUNDLE_README.md` | This file (verbatim). |
| `BUNDLE_PROVENANCE.txt` | git SHA + branch, host, build user, UTC timestamp, R/Python versions, conda env paths, policy refs. |
| `SHA256SUMS.txt` | Deterministic per-file SHA-256 manifest in **GNU `sha256sum` format** (`<hash>  <path>`, lexicographic via `LC_ALL=C sort`). Verifiable directly with `sha256sum -c`. |
| `manifest.tsv` | Same content as `SHA256SUMS.txt` but in 3-column TSV (`relative_path<TAB>sha256<TAB>bytes`), matching the M1 OSF receipt convention at `.planning/amendments/sha256_manifest_m1_frozen.tsv`. Generated by [`src/python/freeze_sha256_manifest.py`](../src/python/freeze_sha256_manifest.py) with `--no-mtime`. |
| `results_identity_ld/fine_mapping/*.json` | 95 SuSiE-RSS fits (~86 MB). |
| `results_identity_ld/fine_mapping/finemap_manifest.tsv` | Fine-mapping manifest (trait, ancestry, region_id, paths). |
| `results/fine_mapping/finemap_summary.tsv` | Real-LD comparator summary (Stage 2 production fire 2026-04-22). |
| `planning/IDENTITY-LD-K2D-FIT-SUMMARY.tsv` | Canonical 96-row K2D summary (snapshot from `.planning/amendments/`). |
| `src/R/figures/fig3_sh2b3_eur_collapse_forest.R` | Fig 3 generator (verbatim). |

Optional (`--include-rds`): `results_identity_ld/fine_mapping/*.fit.rds`
(95 files, ~74 MB extra). The default Fig 3 path reads JSON, not RDS;
include only if a downstream re-analysis needs the binary fits.

## 4. How to build a bundle

From the project root:

```bash
# Default: JSON-only, write to results/track-a-bundles/
bash bin/track-a-repro-bundle.sh

# Custom output dir
bash bin/track-a-repro-bundle.sh --out-dir /rs1/researchers/c/ckclinto/coloc-archives

# Include .fit.rds binaries
bash bin/track-a-repro-bundle.sh --include-rds

# Read-only preview of what would be bundled
bash bin/track-a-repro-bundle.sh --dry-run

# Help
bash bin/track-a-repro-bundle.sh --help
```

Output naming:

```
<out-dir>/track-a-repro-bundle_<git-short-sha>_<UTC-yyyymmdd>.tar.gz
<out-dir>/track-a-repro-bundle_<git-short-sha>_<UTC-yyyymmdd>.tar.gz.sha256
```

## 5. How to extract a bundle

```bash
mkdir -p /tmp/track-a-extract
tar -xzf /path/to/track-a-repro-bundle_<sha>_<utc>.tar.gz -C /tmp/track-a-extract
cd /tmp/track-a-extract/track-a-repro-bundle
ls
```

Expected layout matches §3 above.

## 6. How to regenerate Fig 3 from an extracted bundle

The Fig 3 generator
[`src/R/figures/fig3_sh2b3_eur_collapse_forest.R`](../src/R/figures/fig3_sh2b3_eur_collapse_forest.R)
disk-derives its locked scalars from the K2D summary TSV plus the
identity-LD JSON fits for SH2B3_12q24 EUR (asthma, bmi, hypertension,
stroke, t2d).

Inside the extracted bundle root:

```bash
# 1. Activate the r_coloc env (R 4.4.2 + susieR 0.14.2 + data.table)
RSCRIPT=/rs1/researchers/c/ckclinto/conda_envs/r_coloc/bin/Rscript

# 2. Run the generator. The script resolves inputs relative to its own
#    project root layout, so call it from the bundle root.
"$RSCRIPT" src/R/figures/fig3_sh2b3_eur_collapse_forest.R
```

The generator reads:

- `results_identity_ld/fine_mapping/{asthma,bmi,hypertension,stroke,t2d}.EUR.SH2B3_12q24.json`
- `results/fine_mapping/finemap_summary.tsv`
- `planning/IDENTITY-LD-K2D-FIT-SUMMARY.tsv` (path may need to be aliased
  back into `.planning/amendments/` if the script reads it under that
  exact path; see "Path-aliasing tip" below).

Compare the rendered PDF/PNG to the canonical render in
[`docs/manuscript/figures/`](../docs/manuscript/figures/) at git SHA
recorded in `BUNDLE_PROVENANCE.txt`.

Expected locked-scalar values (from the audit closure tracker):

| Trait | Identity-LD CS yield | Real-LD CS yield | Note |
|---|---|---|---|
| asthma | 0 | 1 | converged |
| bmi | 3 | 8 | non-converged at L=10 |
| hypertension | 10 | 4 | non-converged saturation |
| stroke | 10 | 2 | non-converged saturation |
| t2d | 2 | 9 | converged |

**Path-aliasing tip.** The generator on `main` reads the K2D summary
from `.planning/amendments/IDENTITY-LD-K2D-FIT-SUMMARY.tsv`. After
extracting the bundle to a directory that is *not* a copy of the full
repo, alias the bundled path:

```bash
mkdir -p .planning/amendments
ln -s ../../planning/IDENTITY-LD-K2D-FIT-SUMMARY.tsv \
       .planning/amendments/IDENTITY-LD-K2D-FIT-SUMMARY.tsv
```

This keeps `BUNDLE_PROVENANCE.txt`'s `git_sha` meaningful as a Fig 3
re-derivation receipt.

## 7. How to verify integrity

**Outer (tarball-level):**

```bash
cd /path/to/results/track-a-bundles
sha256sum -c track-a-repro-bundle_<sha>_<utc>.tar.gz.sha256
```

**Inner (per-file inside the bundle):**

```bash
cd /tmp/track-a-extract/track-a-repro-bundle
sha256sum -c SHA256SUMS.txt
```

Both checks should report all OK. The inner manifest is produced via
plain `sha256sum` over a `LC_ALL=C`-sorted file list (deterministic
byte-lexicographic order); the parallel `manifest.tsv` is generated by
[`src/python/freeze_sha256_manifest.py`](../src/python/freeze_sha256_manifest.py)
with `--no-mtime`, the same determinism contract used for the M1 OSF
manifest at `.planning/amendments/sha256_manifest_m1_frozen.tsv`.

## 8. OSF deposit guidance

The Track A amendment record is [`osf.io/az52u`](https://osf.io/az52u).

Manual upload steps (no automated push):

1. Build the bundle: `bash bin/track-a-repro-bundle.sh`.
2. Verify `sha256sum -c <bundle>.sha256` reports `OK`.
3. Log into OSF, navigate to `osf.io/az52u`, upload both
   `<bundle>.tar.gz` and `<bundle>.tar.gz.sha256`.
4. Add a wiki/component note linking the bundle to the audit-closure
   commit (`BUNDLE_PROVENANCE.txt: git_sha`) and to
   [`TRACK-A-AUDIT-RESPONSE-2026-04-26.md`](../.planning/amendments/TRACK-A-AUDIT-RESPONSE-2026-04-26.md)
   Eval 4B.
5. Do not commit the tarball or sidecar to git (gitignored anyway).

## 9. Limitations

- **JSON-only by default.** The 95 `*.fit.rds` binaries (74 MB) are
  excluded. Pass `--include-rds` if a reviewer needs the SuSiE objects
  for a re-analysis beyond Fig 3.
- **No raw sumstats.** Sumstats provenance is the M1 OSF deposit
  (`data/raw/sumstats_v2/sha256_manifest.tsv` →
  `osf.io/az52u/files/k8w7n`). The Track A bundle assumes the M1 deposit
  remains available.
- **No conda lockfiles.** Env reproducibility uses the `envs/*.yml`
  pinned spec; lockfiles are scheduled before Phase 11 submission per
  [`envs/README.md`](../envs/README.md).
- **No automated Fig 3 re-render.** Re-rendering requires the
  `r_coloc` conda env, which is intentionally outside the script.
- **No automated OSF push.** Upload is manual.

## 10. Determinism contract

Two consecutive builds, on the same machine, at the same git SHA, with
the same content under `results_identity_ld/fine_mapping/` and the same
bundled inputs, produce **byte-identical** tarballs and therefore
identical outer SHA-256. (Verified: see `Determinism: PASS` in build logs.)

Mechanism:

- **Tar entry order**: `tar --sort=name`.
- **Ownership**: `--owner=0 --group=0 --numeric-owner`.
- **Tar mtimes**: `--mtime='2026-01-01 00:00:00 UTC'` (constant).
- **Tar format**: `--format=ustar` (no extended/PAX timestamps).
- **Gzip metadata**: `gzip -n` suppresses the original-name and mtime
  fields in the gzip header.
- **Inner manifests**: `find | LC_ALL=C sort -z | xargs -0 sha256sum`
  (GNU format, lexicographic) plus `freeze_sha256_manifest.py --no-mtime`
  (TSV form).
- **Provenance time anchor**: `BUNDLE_PROVENANCE.txt` records
  `commit_utc` (the bundled commit's authored timestamp), **not**
  wall-clock build time. This keeps provenance meaningful while
  preserving byte-stability per commit.

Cross-machine determinism is not guaranteed — `build_user`,
`build_host`, and the `r_version` / `python_version` strings reflect
the build machine. For cross-machine integrity verification, compare
the per-file inner manifest (`SHA256SUMS.txt`) against `BUNDLE_PROVENANCE.txt`
minus the host-specific lines.
